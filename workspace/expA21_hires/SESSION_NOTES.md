# expA21_hires — 入力解像度を 1024x576 → 1536x864 に上げる

## 動機

- 元画像は 1920x1080 が 381 枚、**3840x2160 が 109 枚**、1280x720 が 38 枚（全て 16:9）
- 現行の学習入力 1024x576 では、4K の 109 枚を **0.27 倍**まで潰している
- 公式指標のレバレッジが最大の **weight=3 クラス（迷走神経・靭帯・反回神経など細長い構造）**は
  解像度の影響を最も受けるはず
- **ConvNeXt は完全畳み込み**なので、MaxViT のような window/grid partition の制約がなく、
  32 の倍数でありさえすれば任意サイズを入力できる（MaxViT は img_size を渡して再計算が必要だった）

## 解像度の選定

16:9 かつ 32 の倍数という条件で:
| 解像度 | 画素数比 | 備考 |
|--------|---------|------|
| 1024x576（現行） | 1.0x | |
| **1536x864** | **2.25x** | 今回採用 |
| 2048x1152 | 4.0x | メモリ・時間が厳しい |
| 1920x1080 | — | **1080/32 = 33.75 で使えない** |

## プロトコル

- fold0 ゲート。比較対象は同一レシピ @1024x576 の **0.6734**（convnext_large 224 タグ）
- 224 タグと 384 タグの両方を回す（解像度単独の効果と、事前学習解像度との交互作用を見る）
- キャッシュは `build_cache_hires.py` で生成（元解像度ラベルから再縮小。RGB→ID 変換はやり直さない）
