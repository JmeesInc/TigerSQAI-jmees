# expB03_dino_f2c

**expB02（DINOv3-7B 凍結 + MaxViT 融合）+ expA06 の f2c 階層 loss** の合成（ユーザー方針 2026-08-26）。

## 根拠（fold×task 分析）

- expB02 は f2c なしでも fine 0.62〜0.64（A05 の 0.56〜0.61 より上）= **7B 特徴は fine の表現力に効く**
- expA06 の +0.09 fine は f2c loss による**断片化抑制**
- 機構が異なるため加算を期待。B02 単体は A06 に一貫して負け（f0 −0.026, f1 −0.024）のため
  **B02 の fold2〜4 は中止**（fold2 は 30分で打ち切り → `fold2_aborted`）し GPU を本実験へ

## 構成

- expB02 と同一（MaxViT-Base + DINOv3-7B 凍結注入, γ=0 init, batch2×accum4）
- - `fine2coarse_weight: 0.25` の f2c loss（expA06 と同一実装）

## プロトコル

- fold0 → **ゲート: expA06 fold0 (0.6575) 超えで fold1〜4 + OOF 自動継続**（チェーン内 awk 判定）
- 1 fold ≈ 7.5h

- Wilcoxon: T1 p=0.084/0.087（A06 優位傾向・未有意）、T2 p=0.48/0.75（差なし）
- **判断: 不採用**。f2c loss がある状態では DINOv3-7B 融合の上乗せは消える（表現力の寄与は
  断片化抑制と重複していた）。しかも学習・推論とも 7B forward のコストと Docker 26GB 同梱が必要
- **expA06 が引き続きベスト**。B03 はアンサンブル素材として保持（f0 は単体最高 0.6690）

- fold0 は大勝・fold1 は負けと**割れている**。fold2-4 で決着（各 box で並列、~8h、計 ~$7）
- 運用バグ: `vastai destroy` が対話確認を要求し fold1 の box が破棄されず 1.5h 課金継続
  → `echo y |` パイプで修正済み (collect_one.sh)。offline box 1台も交換対応

- fold1 は f2c で B02 から +0.008 改善したが A06 に届かず。fold0 の結果と合わせて判断
- vast パイプライン (provision→tmux→collect→destroy) は初回から完走。B系 1fold ≈ $2 を確認
