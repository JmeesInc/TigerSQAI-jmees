## Prompt B — T0 レンダラ（ラベルマップ生成器）

```
タスクB: Blender で「内視鏡視点の**クラスIDラベルマップ**」を大量生成するレンダラを実装する。

写実的な画像は不要です（Tier 0）。欲しいのは **クラスIDの2Dマップ**だけです。
ただし光学的にありえない視点を出さないため、カメラモデルだけは物理的に正しく作ります。

## B-1. 出力仕様

1フレームにつき以下を出力:
- `label/{id}.png` — uint8 単チャンネル、画素値 = fine_id (0..30)。
  **必ず Blender の AOV / Object Index (Cryptomatte でなく `pass_index`) で
  クラスIDを直接レンダリングすること。** RGB を後から色引きする実装は禁止
  （アンチエイリアスで中間色が出て破綻するため）。フィルタは必ず最近傍/1px（`filter_size = 0.01`）。
- `depth/{id}.exr` — 線形深度（後段の補助タスク用）
- `meta/{id}.json` — カメラ内部/外部パラメータ、剥離進行度、患者ID、
  可視クラスのリストと画素数、可視ステーションのリスト（タスクD で埋める。今はプレースホルダで可）

解像度は設定可能に。既定 1024x576。

## B-2. カメラモデル（ここが本質）

一様サンプリングは禁止です。以下の物理的制約に従うサンプラを実装してください。

- **ポート位置**: 右胸壁上、概ね第3〜9肋間・中腋窩線〜肩甲骨下角線の範囲に
  3〜4個のポート点をサンプリング。スコープは通常その1つに入る。
- **スコープ**: 硬性鏡。0度と30度斜視鏡を混在（30度が主）。
  視野角は 70〜85度程度の範囲でサンプリング。
  30度斜視鏡は「シャフト軸に対して視軸が30度傾く」ことと、
  **シャフト軸まわりの回転で視野方向が円錐上を動く**ことを正しく実装すること。
- **注視対象**: 後縦隔（食道、気管分岐部、奇静脈、大動脈、気管支）。
  ポート点から縦隔側を向く方向のみ許可。胸壁や肺尖の裏側などを向く姿勢は棄却。
- **挿入深さ**: ポートから対象までの距離を 20〜120mm でサンプリング（近接視野が多い）。
- **ロール**: 実手術では画像の上下方向は一定でない。±30度程度のロールを許可。
- **レンズ歪み**: 樽型歪みを後処理で適用（ラベルマップなので最近傍補間で）。
- 生成した姿勢のうち「主要構造が1つも写っていない」「1クラスが画面の95%以上」などの
  退化フレームは自動棄却するフィルタを入れること。

カメラパラメータはすべて YAML で設定可能にし、**後のタスクCで実データから較正して上書きできる**
インターフェースにしてください（例: 事前分布 YAML を差し替えるだけで分布が変わる）。

## B-3. 脂肪シェルと剥離進行度（最重要）

**これを実装しないと、この合成データは使い物になりません。**

実際の術野では、縦隔構造の大半は縦隔脂肪と胸膜に覆われていて、
剥離した窓からしか露出していません。アトラスをそのまま描画すると
全構造が無遮蔽で写り、実データのラベル統計とまったく別物になります。

したがって:
- 全アトラス構造を包む **脂肪ボリューム**を手続き的に生成する
  （各構造メッシュの膨張和 / メタボール / SDF の union など。手段は任せる）。
  これが `Fatty tissue`。食道周囲のものは `Fatty tissue esophagus` として別クラスに。
- その外側に **胸膜（Pleura）の薄いシェル**を貼る。
- **剥離進行度 t ∈ [0,1]** をパラメータとして持ち、
  術式の手順に沿った順序で脂肪・胸膜を除去していく。
  最低限、以下のフェーズを t の区間として実装:
  1. 胸膜切開前（ほぼ何も露出していない）
  2. 縦隔胸膜切開・下肺靭帯処理
  3. 奇静脈弓の露出・処理
  4. 食道周囲郭清（食道・気管支・心膜が露出）
  5. 上縦隔郭清（反回神経・気管・鎖骨下動脈が露出）→ 大動脈・胸管まで露出
- 除去は「幾何学的に滑らかな窓」ではなく、**不規則な境界**にすること
  （ノイズ変位 or ボロノイ的な破片）。実際の剥離面はギザギザです。
- `Resection area`（剥離済みの露出面）と `Pool of blood`（低い位置に溜まる小領域）を
  手続き的に付与するオプションを入れる。
- **器具（Instrument）**: 単純なシリンダ+顎のプリミティブで十分。
  ポート点から術野に向かって伸びる姿勢を 0〜2本サンプリング。

## B-4. 患者バリエーション

タスクAで (b) に分類した構造については、TotalSegmentator の CT セグメンテーションから
メッシュを起こして、アトラス由来の細構造（神経・胸管など）と合成する経路も実装してください。
最低限、アトラス側を CT 由来の骨格・気管・大動脈に**非剛体で位置合わせする**手段を用意すること
（landmark ベースの TPS / ARAP など、実装が軽いもので可）。
ここは重いので **オプション扱い**にし、単一アトラスだけでも動くようにしてください。

## 成果物
- `render/` 以下に実行可能な Blender Python (bpy) スクリプト一式
- `configs/camera_prior.yaml`, `configs/dissection.yaml`
- 単一コマンドで N フレーム生成できる CLI（並列レンダリング対応）
- 1フレームあたりの想定レンダリング時間の見積もり
- 生成物の簡易可視化スクリプト（ラベルマップを labelmap の色で着色して PNG 化）

## 禁止事項
- クラスIDを RGB 経由で出すこと
- カメラ姿勢を一様サンプリングすること
- 脂肪/胸膜の遮蔽モデルを省略すること

## Prompt C — 爆発案①: 実データをアトラス空間に登録し、カメラ分布を較正する

```
タスクC: 実データのラベルマップ（私の手元にある。あなたには渡さない）を
アトラス空間に登録して、実際の手術で使われているカメラ姿勢の分布を推定する。

目的は2つ:
1. タスクB のカメラ事前分布を「架空の設定」から「実データ由来の分布」に較正する
2. 各実フレームに推定カメラ姿勢を付与する → タスクD の空間カービングの入力になる

## 前提
- 私の手元には約520枚の実フレームの**クラスIDラベルマップ**（30クラス）があります。
  画像そのものではなく、ラベルマップだけを使う設計にしてください（見た目のドメインギャップを回避できる）。
- 微分可能レンダリングによる完全な最適化は時間的に困難と見ています。
  **まず render-and-compare の検索ベースで解き、必要なら微分可能レンダリングで精密化**、
  という2段構成を提案します。この方針が妥当か、より良い代替があるかも述べてください。

## C-1. Stage 1: 検索ベースの粗い姿勢推定
- タスクB のレンダラで、カメラパラメータ空間を粗く覆う **参照バンク**を生成（例: 10〜50万枚）。
- ラベルマップから**姿勢に敏感で見た目に鈍感な記述子**を設計する。最低限:
  - クラス出現の有無ベクトル（30次元 binary）
  - クラス面積比ベクトル（30次元）
  - クラス重心の画像座標（30x2、欠損マスク付き）
  - クラス間の隣接（境界共有長）行列（30x30、上三角）
  - クラスごとの2次モーメント（伸長方向）
  これらを結合した記述子で、実フレーム → 参照バンク の最近傍検索を行う。
  スケール・回転の扱い（ロール不変にするか否か）を明示的に設計すること。
- 記述子の距離だけでなく、**ラベルマップ同士の直接一致度**（クラス別 IoU の重み付き平均）で
  上位候補を再スコアリングする。

## C-2. Stage 2: 微分可能レンダリングによる精密化（オプション）
- nvdiffrast または PyTorch3D を使い、Stage 1 の初期値からカメラ外部パラメータ
  （+ 必要なら剥離進行度 t と少数の形状パラメータ）を勾配法で最適化。
- 損失はソフトなクラス別 IoU / soft-Dice。離散ラベルの微分可能化の方法を明記すること。
- **収束しない/局所解に落ちる**ことを前提に、失敗検出（損失閾値・多初期値）を入れること。

## C-3. 出力と較正
- `poses/{frame_id}.json`: 推定カメラ姿勢、信頼度スコア、剥離進行度、上位K候補
- 推定姿勢の集合から **カメラ事前分布を再推定**し、
  タスクB の `configs/camera_prior.yaml` を上書きする形式で書き出すスクリプト
- 信頼度の低いフレームを除外する基準の提案

## 現実的な評価をしてください
このアプローチは、単眼・テクスチャなし・大きな個体差・遮蔽ありという条件下での
姿勢推定であり、難しいことは理解しています。
「どこで失敗しそうか」「失敗したときに何が代替になるか」を必ず書いてください。
うまくいくという前提のコードだけ書かないこと。
```

## Prompt D — 爆発案②: ステーション体積の空間カービングと、物理ベース Task3

```
タスクD: リンパ節ステーションの3D体積をアトラス空間に定義し、
Task3（ステーション可視性のマルチラベル分類）を「分類」ではなく
「カメラ姿勢推定 + 幾何的可視判定」として解く経路を作る。

## 背景と狙い
現状 Task3 は画像→14ラベルの multi-label 分類（CV: weighted F1 0.7255 / AUROC 0.8979）で解いています。
これは未知施設への外挿に弱い懸念があります。
ステーションは本質的に「3D空間の領域」であり、可視性は「カメラ視錐台とその領域の幾何関係」です。
これを明示的にモデル化したい。

## D-1. ステーション体積の獲得（2経路。両方作ってください）

### 経路1: 命名法ベース（タスクA-3 の結果が確定したら）
確定した命名法の定義（CTランドマーク基準の境界）に従って、
TotalSegmentator のラベル（気管、主気管支、大動脈、奇静脈、椎体、食道、肺、横隔膜 など）から
**手続き的に各ステーション体積を構成する** DSL/コードを書いてください。
例: 「気管分岐部の下、左右主気管支に挟まれ、食道の前」= 7 のような定義を
ブーリアン演算と方向条件で書けるようにする。

### 経路2: 空間カービング（命名法が確定しなくても動く。こちらを本命に）
タスクC で得た各実フレームの推定カメラ姿勢と、そのフレームの
「見えているステーションのリスト」（実データのラベル。私がローカルで持っている）から、
**各ステーションが存在しうる3D領域を逆算する**:
- あるステーション s が「見えている」フレームの視錐台 ∩（遮蔽を考慮した可視領域）→ s は必ずここに含まれる
- s が「見えていない」フレームの可視領域 → s はここに含まれない（カービングして削る）
- これを全フレームで積み上げて、アトラス空間のボクセルグリッド上に
  各ステーションの存在確率場を作る。
- 姿勢推定の誤差とラベルノイズを吸収するため、ハードなブーリアンではなく
  **確率的な更新（対数オッズの加算など）**にすること。

経路2の妥当性と必要フレーム数の目安を述べてください。約520枚（ラベル付きは約310行）で足りるか。

## D-2. 合成 Task3 データの生成
タスクB のレンダラに、可視ステーション判定を組み込む:
- 各ステーション体積に対し、カメラから見て「遮蔽を考慮した上で一定画素数以上見えているか」で
  binary ラベルを決める。閾値は設定可能に。
- これで **カメラ姿勢のサンプル数だけ Task3 の学習データが無料で作れる**。
- 合成ステーションラベルの共起行列が実データの共起行列と整合するかを
  後から検証できるよう、共起行列を出力すること。

## D-3. 物理ベース Task3 モデル

## Prompt E — 堅実案: マスク条件付き画像生成による見た目拡張（独立して回せる）

タスクE: 既存の実マスクを条件として「同じレイアウト・違う見た目」の手術画像を生成し、
