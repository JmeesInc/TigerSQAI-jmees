# Linux 検証 + 較正ラウンド3 の指示（2026-09-09）

Claude Code（Linux GPU サーバ、実データ保有）で B改訂/C Stage1 を再現検証した結果と、次の指示。
**内容はすべて集計値・公開情報のみ。Astra に渡してよい。**

## 1. 再現できたこと（Linux 側で確認済み）

- Z-Anatomy を GitHub の raw URL から取得し、**Startup.blend の SHA-256 が
  `9f08a17ea0115fed80b2a73ecdf0a1bc2ab2f6956f37c593ce23d513ea35afcd` で完全一致**。同一アセットで再現可能
- Blender 4.5.3 LTS を非 root で展開して動作。**15 テスト全通過**（render 7 + registration 8）
- CUDA・4 並列で 32 枚 177〜237 秒（**5.5〜7.4 秒/枚**）。Mac CPU の 2.4 秒/枚 とは
  棄却率の差で単純比較不可。**バンク 2048 枚は 3〜4 時間、8192 枚は 12〜16 時間**の見込み
- 実マスクは **mode L / 1024x576 / 16:9 / ID 0..30** で `registration.features.read_label` の要件を満たす

## 2. 診断: 統計不一致の原因は2つに分解できた

A/B を 3 本回して切り分けた（各 24〜32 枚、同一 seed 系列）。

### 原因1: 心膜 proxy が下肺静脈(12)を飲み込んでいる【確定】

| 条件 | Pericardium(11) | IPV(12) |
|---|---:|---:|
| 実データ | 70.8% | **58.3%** |
| provisional 有効 | 62.5% | **0.0%** |
| `--disable-provisional-structures` | 0.0% | **4.2%** |

心膜 proxy を切ると IPV が出現する = **proxy が IPV を遮蔽している**。
原因は source_objects が左右心房・心室で、`margin_mm: 1.5` の膨張和が肺静脈の心房流入部を包むため。
→ **修正案**: 心房を source から外す／margin を下げる／IPV を心膜 proxy から明示的に減算する。
IPV は実データ 出現 58.3%・面積 3.49% の主要クラスなので優先度は高い。

### 原因2: カメラと剥離窓が結合していない【本命・構造的】

`visible_class_count` フィルタ除去、剥離窓 0.45 倍縮小の 2 本で検証:

| 指標 | 実データ | B改訂(現行) | フィルタ除去 | 窓 0.45倍 |
|---|---:|---:|---:|---:|
| Trachea 出現 | 58.0% | 100.0% | 96.9% | 53.1% |
| SVC 出現 | 11.6% | 83.3% | 71.9% | 65.6% |
| Pleura 面積 | 16.44% | 8.00% | — | **64.75%** |
| Esophagus 出現 | 85.6% | 91.7% | 78.1% | **18.8%** |
| 可視クラス数 中央値 | 15 | 14 | — | **8** |
| 出現率の絶対差 合計 | 0 | 786pp | — | **850pp** |

- フィルタ除去は数 pp しか動かない → **フィルタは主犯ではない**（ただし上縦隔バイアスに寄与はする）
- 窓縮小は**逆方向に振り切れる**。Pleura が画面の 65% を占め、深部が何も見えなくなる
- つまり現状は「窓を広げる＝全部見える／狭める＝何も見えない」の 1 次元しかない

**実データはこの 1 次元上に存在しない**: Pleura 面積 16.4%（大きい）**かつ** 可視クラス数 15（多い）
**かつ** 背景 18%。これは「**狭い露出窓を至近距離から覗いている**」状態であり、
現在の実装は「窓の大きさと無関係にランドマークを注視する」ため再現できない。

## 修正1（確定バグ）: 心膜 proxy が下肺静脈(12)を遮蔽
provisional 有効で IPV 出現 0.0%、--disable-provisional-structures で 4.2%。

## 修正2（本命）: カメラと剥離窓を結合する
現状はカメラが「剥離窓の位置と無関係に」ランドマークを注視するため、
窓を広げると全構造が同時に見え、狭めると胸膜しか見えない、の1次元しか作れない。
A/B の実測（実データ / B改訂 / 窓0.45倍）:
  Pleura面積  16.44% / 8.00% / 64.75%
  可視クラス数中央値  15 / 14 / 8
  Esophagus出現 85.6% / 91.7% / 18.8%
  出現率の絶対差合計   0 / 786pp / 850pp

実データは「Pleura面積16.4%（大きい）かつ 可視クラス数15（多い）かつ 背景18%」で、
これは **狭い露出窓を至近距離から覗いている** 状態。現在の1次元では到達できない。

したがって:
- **注視点を剥離窓の中心（およびその近傍のジッタ）から選ぶ**。ランドマーク注視は、
  そのランドマークが現在の進行度 t で露出している場合のみ許可する
- **撮影距離を窓のサイズに結合する**: 露出窓が視野の大部分（例: 短辺の 50〜80%）を
  占める距離を解いてサンプリングする。窓が小さいほど近づく
- 窓の半径は B改訂の値を維持してよい（0.45倍は行き過ぎだった）。結合が入れば
  窓サイズは「露出範囲」だけを決め、「どれだけ写るか」はカメラ距離が決める
- 結合の強さ（窓中心注視の確率、視野占有率の分布）は設定ファイルに出すこと
