# Tier 1 レンダリング依頼（2026-09-11）— img2img の種画像を作る

## 背景: なぜ今これが必要か

ラベルマップのみを条件とした生成（text2img + ControlNet）を 3 ラウンド試したが頭打ちになった。

| 構成 | 合成ラベル条件での忠実度 (weighted Dice) |
|---|---:|
| v1 ControlNet のみ | 0.1364 |
| v2 + UNet LoRA | 0.1570 |
| v3 + depth + class-aware + 臓器別段階生成 | 0.1546 |
| **参考: 実ラベル条件（v2）** | **0.3510** |
| 参考: 実画像そのもの（上限） | 0.4912 |

**実ラベルなら 0.35 出るのに合成ラベルだと 0.15** → 生成モデルの能力不足ではなく、
**平坦なラベルマップだけでは条件が弱く、モデルの事前分布に負けている**。

先行研究 [SimuScope](https://arxiv.org/abs/2412.02332) (WACV25) は同じ問題に対し
**シミュレータのレンダリング画像を img2img の種にする**方式を採っている。
初期潜在が既に正しい空間構造と陰影を持つため、拡散は「レイアウトを発明する」必要がなく
「質感を足す」だけでよくなる。これが本依頼の目的。

## 依頼内容

既存の Tier0 パイプラインに **RGB レンダリング出力**を追加する。

### 最重要の制約
- **既存の label / depth と完全に画素一致**させること（同一カメラ・同一フレームで、
  できれば**同じレンダリングパスの中で**同時出力する）。別パスで撮り直すとズレる
- 出力: `rgb/{frame_id}.png`（8bit RGB、label と同解像度）

### 写実性は要求しない
最終的な写実性は拡散モデルが付与する。**種画像に必要なのは以下の 3 点だけ**:
1. **内視鏡照明による正しい輝度構造**（どこが明るくどこが陰か）
2. **クラス間の材質の区別**（隣接クラスが同じ見た目にならないこと）
3. **高周波のテクスチャ**（拡散が手がかりにできる微細構造）

→ **Cycles ではなく EEVEE、サンプル数は最小で構わない。**速度優先。

### 照明モデル
- **カメラと同軸の点光源**（内視鏡は光源とカメラが同じ場所にある）
- **r^-2 の距離減衰**を明示的に効かせる。これが内視鏡画像の最大の特徴で、
  「近いものは白飛び、遠いものは真っ暗」という輝度構造を作る
- 環境光はほぼゼロ（胸腔内に外光は入らない）
- 軽いフォグ/ヘイズ（電気メスの煙）をオプションで

### 材質パラメータ（実データ 264 枚から実測、照明の低周波成分を除去した値）

**絶対的な色は指定しない**（画角と照明で動くため）。以下の**相対的な材質特性**で指定する。
全データは `real_class_texture.json`。

- **微細コントラスト** → bump / displacement の強さ（0.18〜0.41 の範囲を材質差として反映）
- **エッジ密度** → プロシージャルノイズのスケール（大きいほど細かい模様）
- **ハイライト%** → specular / roughness（0.003 のマットから 0.589 の強光沢まで **2 桁の差**がある）
- **異方性は 1.16〜1.42 でほぼ等方的** → 方向性テクスチャは不要、等方ノイズでよい

特に効く対比:
- **Pleura（平滑・光沢）vs Resection area（粗い・マット寄り）** — 面積が大きく画面を支配する 2 クラス
- **Pericardium / IPV（ハイライト ~0.003）vs 神経・肺動脈（~0.5）** — 桁違いの光沢差
- **Pool of blood** は微細コントラスト最大 — 液面として作る

### やらなくてよいこと
- 写実的な PBR マテリアルの作り込み
- サブサーフェススキャタリングの物理的正確さ
- テクスチャ画像の用意（プロシージャルノイズで十分）
- 血管の解剖学的に正確な走行パターン（拡散が補う）

## 成果物
- `render/` に RGB 出力を追加（既存 CLI にフラグ、例 `--emit-rgb`）
- `configs/materials.yaml` — クラスID → {base_hue, roughness, specular, bump_strength, noise_scale}
  を上表の実測値から設定（値は設定ファイルで差し替え可能に）
- 既存 2000 フレーム（`outputs/pretrain_2k`）と**同一カメラ・同一 seed で RGB を再出力**できること
- 1 フレームあたりのレンダリング時間の実測

## 検証
`rgb/` と `label/` の画素対応を検査するスクリプト（クラス境界で RGB の不連続が立つことを確認）。
ズレていると img2img の意味が消えるので、ここは必ず自動テストにすること。
