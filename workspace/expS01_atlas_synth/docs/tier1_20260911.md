# Tier 1 RGB seeds, 2026-09-11

新規生成はEEVEE 1 sampleでCombined RGB・Depth・FineID VALUE AOVを**1回のrender.render**から保存する。FineIDはObject InfoのObject Index（obj.pass_index）を直接接続し、RGB色引き・Cryptomatteは使わない。EEVEE4.5.9では通常のObject Indexパスは出力されないことを実機で確認した。AOVに非整数があれば失敗させる。透明材質・ジオメトリdisplacement・motion blurは使わない。bumpは法線だけを変える。

RGB/label/depthは同一の最近傍lens warpを共有する。RGBだけに画角変更・別カメラ・拡大縮小を加えない。RGBは線形CombinedをReinhard→sRGBへ変換した8bit RGB PNG。材質のbase_hueは**例示色**で、実データの色を推定したものではない。公式ラベル配色もRGB材質には流用しない。

## 実行

```bash
python -m render.generate --frames 128 --output outputs/tier1 \
  --resolution 1024 576 --workers 4 --blender /path/to/blender \
  --allow-provisional --emit-rgb --materials configs/materials.yaml
python -m render.audit_outputs outputs/tier1
python -m render.alignment outputs/tier1 --require-edge-evidence
python -m render.verify_tier1 --blender /path/to/blender --output outputs/light_verification
```

EEVEEのGPU選択はBlenderのgraphics backendに従う。`--device CUDA`等はCyclesのデバイス設定であり、EEVEEのCUDA選択を意味しない。Linux/headless環境のEEVEE graphics contextはLinux側で要動作確認。新規外部アセット・重み・画像テクスチャの取得はない。元のZ-Anatomyの来歴とライセンスは従来どおり。

## 照明・材質

カメラ先端と同位置のPOINT光源を毎フレーム更新。点光源の逆二乗減衰を使い、EEVEEの有限範囲fadeが胸腔内に影響しないようcutoff_distance_mm=100000とする。環境Strength=0。energy=60000は**mm座標系での未較正レンダリング強度**であり、医療機器の実測ワット値ではない。単位設定scale_lengthだけを物理的放射測定への変換と解釈しない。energy/exposureは設定可能。

共有264枚の集計を `assets/real_class_texture.yaml` に保存した。全31 IDの `configs/materials.yaml` には次の単調な初期変換を記載する。欠測IDは `fallback_no_shared_measurement`。画像統計は照明・画素尺度・形状にも依存するため、材質物性が同定されたとは扱わない。

- micro_contrastの0.18–0.41をbump_strengthの0.06–0.30へ線形対応。
- edge_densityの0.057–0.136をnoise_scaleの0.5–2.0 mm^-1へ線形対応。
- v=log(1+specular_pct/0.003)/log(1+0.589/0.003) としてroughness=0.93−0.73v、specular=0.015+0.485v。
- 等方3D Noiseをworld positionで参照し、物体・フレームでUVスケールを変えない。凹凸距離0.25mmは法線計算用で、実メッシュは変えない。

hazeは既定無効。オプションでは保存済み軸深度を使う指数減衰と灰色の混合を同一画素へ適用する軽量近似。3D煙の散乱を解いたものではない。

## 既存2000枚の再出力

このMacに `outputs/pretrain_2k` は存在しないため、その2000枚自体は未実行。Linuxの**合成バッチ**に以下を使う。元フォルダは上書きしない。

```bash
python -m render.replay_rgb outputs/pretrain_2k \
  --output outputs/pretrain_2k_rgb --workers 4 --blender /path/to/blender
```

保存されたmetaのカメラ・K・歪みを直接使用し、採択サンプラを再実行しない。新しい生成では採択時のprocedural geometryを `geometry/{id}.npz` に保存し、SHAをmetaへ記録する。旧バッチでは `work/base.npz`、`work/envelope.npz`、resolved_configs、provenance、metaが必要。進行度サンプリングの乱数消費を再現して形状を再構築し、剥離meta一致を検査する。元が `--progress` 固定なら `--legacy-progress-mode fixed` を指定する。旧バッチに器具がありgeometry snapshotがない場合は、安全に復元できないため停止する。seedとカメラだけで元形状を推測しない。

**Cycles製の既存ラベルとの完全一致はEEVEEへ切替えるだけでは保証できない。** 256×144の2枚では各2画素が違った。既定の再出力はラベル差が1画素でもあれば停止しRGBを書かない。深度もrtol1e-5/atol0.001mmで検査する。`mismatch/{id}.json`に差分を記録する。既存ラベルは変更しない。

ユーザーが新しい制御画像への置換を選んだ場合のみ `--rerender-triplet` を加え、同じ元カメラからEEVEE製RGB/label/depthを揃えて使う。旧label/depthと混在させない。既存Cycles制御を固定する場合の明示的な互換経路として `--engine cycles --device CUDA` も実装しているが、速度優先のEEVEE要件の例外となるため、ユーザー選択なしに自動fallbackしない。このCycles互換経路は今回未実行・未検証。

## 画素検証の範囲

`render.alignment` は隣接クラス間のRGB差とクラス内RGB差を比較し、境界コントラストが0.002を超え、クラス内平均の1.05倍を超えることを検査する。意図的に4pxずらした二領域fixtureが失敗する単体テストを含む。影・似た色・bumpによって境界が見えない/別のエッジが増えることがあるので、この画像診断単独を幾何学的一致の証明とはしない。同一renderのID AOVと共通warp、再出力比較を合わせて確認する。

参照: [Blender 4.5 render passes](https://docs.blender.org/manual/en/4.5/render/layers/passes.html)、[SimuScope](https://arxiv.org/abs/2412.02332)。SimuScopeを着想の参照とし、その実装や学習効果の再現を主張するものではない。


## 実測・検証結果

Mac / Blender4.5.9 / EEVEE / 1 sample。最終設定、1024×576の4枚:

- 準備7.33秒、全体18.56秒（4.64秒/枚、準備・候補棄却・PNG/EXR保存込み）。採択されたrender処理の中央値0.401秒。
- 保存geometry・cameraから2 workerで4枚再出力: 全体10.03秒。RGB・label・depth全12ファイルのSHA-256が元出力と完全一致。ラベル差0画素、深度差0mm。
- 境界診断4/4通過。クラス境界/内部コントラスト比16.86–26.55。
- 29単体テスト通過（render21＋registration8）、4枚の出力監査通過。
- 同軸POINT照明の独立EEVEEテスト: 50mm/100mmで線形RGB比4.000000。自動範囲fadeを修正する前は4.2175でテストに失敗したため、最終設定では明示的cutoffを用いた。
- 旧Cyclesバッチの再出力ガードは2画素差を検出して停止し、RGB未保存を確認。

4枚だけの短時間測定なので2000枚の所要時間への単純外挿はしない。shader compile/cache、GPU競合、候補棄却率、保存IOが影響する。Linux EEVEЕと実際のpretrain_2kは未検証。今回の追加はTier 1の画像出力であり、Round 4の解剖分布ゲートを通過したと主張するものではない。
