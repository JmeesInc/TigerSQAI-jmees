# ラウンド3: IPV保護・窓とカメラの結合

Linux検証のコミット `2acdaf2` を確認して取り込んだ。Blender4.5.3/CUDAでの再現性と時間はLinux担当者の報告、以下の追加検証はMac/Blender4.5.9/CPUによる。実画像・実マスクは見ていない。

## 実装変更

1. 心膜proxyの膨張・閉処理の**後**に、元の左右IPVメッシュのボクセル充填領域＋4mm clearanceを減算する。後から膨張で穴を埋め戻さない。`provisional.pericardium.subtract_ipv` と `ipv_clearance_mm` で制御する。静脈の実メッシュは変更しない。4mmは暫定安全幅で、心膜反転部の解剖学的再構築ではない。
2. tに対応する実際の除去maskと、被覆union外表面の交差から開口候補を得る。各ポートに向いた面だけを使い、同じ窓の複数の局所中心を候補化する。中心に近い候補ほど高い重みを与える。初期の単一中心案は進行度によって衝突ばかりになるため採用しなかった。
3. 開口中心を85%の確率で注視し、残りは現在の除去mask内にあるランドマークに限る。ジッタ後もmask内か検査する。「露出」は被覆が除去済みという意味で、別臓器からの遮蔽がないことの保証ではない。レンダリング後の画素フィルタは維持する。
4. 開口中心から残存胸膜外表面までの最近距離を、局所的な内接開口の有効半径rとする。除去楕円体全体の半径とは異なる。距離を `d=2r/[occupancy × min(W/fx,H/fy)]` で求める。占有率は切断正規[0.50,0.80]。**face-onの局所開口近似**であり、不規則な開口の投影輪郭の実測占有率ではない。このモデル・r・占有率をmetaへ保存する。
5. 解いた距離が撮影距離/ポート距離/挿入量の範囲外なら棄却する。30度円錐モデルとシャフト衝突検査は維持する。広すぎる窓を無理に収めるための距離clampは行わない。
6. ポート集合は上側の従来ランドマークに加え、設定上有効な下縦隔窓のanchorにも到達できることを要求する。ポート3〜4個・第3〜9肋間の範囲は維持する。

「狭い窓を近くから見る」は集計と整合しうる作業仮説であり、3つの周辺統計から一意に証明された撮影状況ではない。この修正で統計一致するかは128枚以上で判定する。

## 設定

`configs/camera_prior.yaml: window_coupling` に有効/無効、中心注視確率、占有率、中心近傍ジッタ、ポートに向く面の角度、候補中心の間隔/数/重みを置いた。窓の名目半径はB改訂版を維持した。試行上限は5000へ増やしたが、物理条件は緩めていない。失敗フレームを省いて成功と報告しない。

`configs/acceptance.yaml` に基準値786pp、胸膜8%、可視クラス中央値14、背景中央値6.7%を固定した。レポートには常に4指標のbaseline・target・実測値・改善判定を出す。単一指標では合格にせず、**128枚以上で4指標の目標までの距離がすべて厳密に縮まった場合だけ合格**。可視クラス数中央値15が目標であり、16はbaseline14と同距離なので合格ではない。

バンクには追加で12/8/9すべての可視画素が必要。`registration.generate_bank` と `registration.bank` は合格レポートを必須にし、不合格なら処理前に止める。バンク自体を索引化する際にも12/8/9の出現を再検査する。ゲート通過前に2048枚を生成しない。

## 可視クラス数priorの補正

下縦隔も含む候補では16クラス付近が多かった。単純なGaussian優先度だけでは、その提案分布が掛かったままになる。最終候補は、公開アトラス128枚のクラス数ヒストグラムp(n)で補正し、`accept(n) ∝ Gaussian(n;15,2) / p(n)` を最大1へ正規化して使う。`quality.visible_class_count.soft_preference.proposal_counts` にその合成pilot集計を明示した。11〜18の帯は維持し、条件を15に固定するフィルタではない。

p(n)は新しい候補集合・患者形状・ポート分布で変わるため、これで必ず中央値15になるとは保証しない。実マスクのフレーム情報を使った補正ではなく、実側から使うのは共有済み集計の目標値のみ。生成候補に対する選択圧なのでクラス別出現率も変わり、4指標をすべて再評価する。不要な場合は `soft_preference: null` で無効にできる。

## 2026-09-09 Mac側の実測

すべて公開Startup.blend、256×144、Blender 4.5.9 CPU・2 worker、各128枚。共有された実側528枚の集計と比較した。各実験は同じseed系列を使った較正実験で、独立holdoutではない。サンプラ変更に伴って乱数消費・採択姿勢も変わるため、心膜修正単独の因果効果をこの比較から分離できない。

最終バッチは `outputs/round3_importance128`。出現率誤差合計は基準から152.26 pp（19.4%）減少。背景は目標を超過しているが、目標との差は11.30→8.49 ppへ縮小。可視クラス数のp10/median/p90は12.7/15/17。最終設定は既定 `configs/camera_prior.yaml`、幾何のみの比較設定は `configs/camera_prior_round3_geometry.yaml`。後者は中央値16で不合格なのでバンクには使わない。

IPV(12)出現は **45/128=35.16%**、右下肺靭帯(8)は **44/128=34.38%**、左(9)は **53/128=41.41%**。IPVが0%の状態から回復し、必須3クラスの未出現は解消した。IPV平均面積は0.21%で実側3.49%に遠く、出現率も実側58.3%には達していない。心膜proxyはprovisionalのまま。

残る主な偏り: 器具35.16%（実90.2%）、血液7.03%（実53.6%）と不足し、SVC57.03%（実11.6%）、肺動脈55.47%（実7%）、迷走神経96.88%（実40.7%）などは過剰。4指標通過は全クラスの一致や登録精度の保証ではない。全31クラス差分は `round3_results_20260909.md` に保存した。

21テスト（render13＋registration8）通過。最終128枚すべてのL/uint8ラベル、Z float32/mm EXR、meta画素数、硬性鏡幾何、窓サイズと距離の式を監査した。公式配色による12枚のコンタクトシートも目視確認した。Macの実効時間は3.54秒/枚（起動・準備・棄却込み、並列壁時計時間/N）。Linux/CUDAでの修正版速度は未測定。

Linuxでは上記128枚コマンドを先に再実行し、同じ4指標と12/8/9を確認してから2048枚へ進む。こちらではバンクを生成していない。合格レポートにはresolved設定を埋め込み、生成前と索引構築時の両方で設定一致を要求する。seed/device/worker threads等の実行条件だけを比較から除外し、解像度・幾何・品質priorの変更は再評価を必要とする。アセットの実ファイル同一性は別途既存のSHA検証で確認する。設定一致だけではコード版の一致を保証しないため、Linux側も今回のコミットを使用すること。
